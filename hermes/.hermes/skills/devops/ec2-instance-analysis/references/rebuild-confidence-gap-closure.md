# IaC Rebuild Confidence — Gap Closure Patterns

After initial IaC export (OpenTofu + Ansible), audit for gaps that would prevent
a clean rebuild from scratch. Common gaps and their fixes:

## Gap audit checklist

For each component on the live instance, verify the Ansible role can:
1. Install the binary/package (not just configure it)
2. Create the system user/group
3. Deploy the systemd unit
4. Run database migrations (if applicable)
5. Obtain TLS certificates (if applicable)
6. Generate installer packages requiring Docker (if applicable)
7. Enroll/register with external services (if applicable)

## Fleet: `prepare db` migration task

Fleet requires database migrations before first start. Add after binary install,
before service enable:

```yaml
- name: Run Fleet database migrations
  command: "{{ fleet_binary_path }} prepare db --no-prompt --config {{ fleet_config_path }}"
  environment:
    FLEET_MYSQL_PASSWORD: "{{ fleet_mysql_password }}"
  when: not fleet_binary_stat.stat.exists
```

Key: `--no-prompt` for non-interactive. Gate on stat check (not `fleet_download.changed`) for reliable idempotency — `get_url` may report `changed` on re-download even when binary already exists.

### Stat-based idempotency (recommended over download.changed)

`get_url` register `.changed` is unreliable for gating downstream tasks. Use stat:

```yaml
- name: Check if Fleet binary exists
  stat:
    path: "{{ fleet_binary_path }}"
  register: fleet_binary_stat

# ... download, extract, install tasks ...
  when: not fleet_binary_stat.stat.exists
```

### Fleet binary extraction (nested dirs)

Fleet release tarballs have nested structure: `fleet_v4.70.1_linux/fleet`. Extract to temp dir then copy binary:

```yaml
- name: Create Fleet extract directory
  file:
    path: /tmp/fleet-extract
    state: directory
  when: not fleet_binary_stat.stat.exists

- name: Extract Fleet binary
  unarchive:
    src: "/tmp/fleet.tar.gz"
    dest: "/tmp/fleet-extract/"
    remote_src: yes
  when: not fleet_binary_stat.stat.exists

- name: Install Fleet binary
  copy:
    src: "/tmp/fleet-extract/fleet_v{{ fleet_version }}_linux/fleet"
    dest: "{{ fleet_binary_path }}"
    remote_src: yes
    mode: "0755"
    owner: root
    group: root
  when: not fleet_binary_stat.stat.exists
  notify: restart fleet
```

Same pattern for fleetctl: `fleetctl_v4.70.1_linux_amd64/fleetctl`.

### Fleet download URL format

Correct GitHub release asset names (NOT `fleet.zip`):
- Fleet server: `fleet_v{version}_linux.tar.gz`
- fleetctl: `fleetctl_v{version}_linux_amd64.zip`

```yaml
fleet_download_fleet: "{{ fleet_download_base }}/fleet_v{{ fleet_version }}_linux.tar.gz"
fleet_download_fleetctl: "{{ fleet_download_base }}/fleetctl_v{{ fleet_version }}_linux_amd64.zip"
```

### Docker apt_key deprecation (Ubuntu 22.04+)

`apt_key` module is deprecated. Use `get_url` to keyring:

```yaml
- name: Create keyrings directory
  file:
    path: /etc/apt/keyrings
    state: directory
    mode: "0755"

- name: Add Docker GPG key
  get_url:
    url: https://download.docker.com/linux/ubuntu/gpg
    dest: /etc/apt/keyrings/docker.asc
    mode: "0644"

- name: Add Docker apt repository
  apt_repository:
    repo: "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu jammy stable"
    filename: docker
    state: present
```

Also: `community.docker.docker_image` module requires newer Ansible. On Ansible 2.10 use `command: docker pull` instead.

### Orbit TUF expiration pitfall

`fleetctl package` with `--update-url https://tuf.fleetctl.com` + channel flags will fail if TUF root.json is expired:

```
Error: initialize updates: failed to update metadata: client update: tuf: failed to decode root.json: expired at 2026-01-08
```

Fix: use `--disable-updates` flag instead of `--update-url`, `--orbit-channel`, `--osqueryd-channel`, `--desktop-channel`.

### Orbit cert variable scoping

Ansible roles don't share variables. If orbit role needs certbot's cert path, define it in orbit defaults (not certbot defaults):

```yaml
# roles/orbit/defaults/main.yml
orbit_cert_source: "/etc/fleet/certs/fullchain.pem"
```

Reference as `{{ orbit_cert_source }}` in orbit tasks, NOT `{{ certbot_fleet_cert_dest }}`.

## Orbit: install via `fleetctl package` (not apt)

Orbit (Fleet's osquery agent) is NOT in any apt repo. It's installed via a .deb
generated by `fleetctl package`, which requires Docker on the build machine.

```yaml
- name: Check if fleet-osquery already installed
  command: dpkg -s fleet-osquery
  register: orbit_installed
  changed_when: false
  failed_when: false

- name: Generate orbit .deb installer via fleetctl
  command: >
    fleetctl package
    --type deb
    --arch amd64
    --enroll-secret {{ orbit_enroll_secret }}
    --fleet-url {{ orbit_fleet_url }}
    --fleet-certificate {{ orbit_cert_path }}
    --disable-updates
    --fleet-desktop
  args:
    chdir: /tmp
  when: orbit_installed.rc != 0

- name: Find generated .deb
  find:
    paths: /tmp
    patterns: "fleet-osquery*.deb"
  register: deb_files
  when: orbit_installed.rc != 0

- name: Install fleet-osquery .deb
  apt:
    deb: "{{ deb_files.files[0].path }}"
    state: present
  when: orbit_installed.rc != 0 and deb_files.files | length > 0
  notify: restart orbit
```

Key: `fleetctl package` generates `fleet-osquery_*.deb` in cwd. The .deb includes
orbit binary, systemd service, and enrollment config baked in. Must run after
Docker role (fleetctl uses Docker to build packages).

Orbit binary self-updates after install (version in dpkg may be older than
`orbit --version` output). With `--disable-updates`, orbit won't pull updates
from TUF — acceptable for reproducible builds.

## Playbook ordering dependencies

Order matters for first-time provisioning:

```
common → mysql(skip) → redis → docker → fleet → certbot → nginx → orbit → wazuh
```

Critical ordering constraints:
- **common before everything**: creates fleet user, cert dirs, log dirs
- **docker before fleet**: fleetctl package needs Docker to build orbit .deb
- **fleet before certbot**: certbot copies certs to /etc/fleet/certs/ (created by fleet/common)
- **certbot before nginx**: nginx config test (`nginx -t`) fails if TLS certs don't exist yet
- **fleet before orbit**: orbit needs Fleet URL + cert to enroll

## OpenTofu: `aws_security_group_rule` import format

Importing a cross-account SG rule (e.g. RDS SG allowing Fleet instance) requires
a composite ID. The CIDR slash does NOT need escaping:

```bash
# Format: <sg-id>_<type>_<protocol>_<from-port>_<to-port>_<cidr>
tofu import $VARS aws_security_group_rule.fleet_to_rds "sg-0cf93668_ingress_tcp_3306_3306_172.16.3.195/32"
```

NOT `cidr_blocks` — just the raw CIDR as the source segment.

## OpenTofu: `aws_route53_record` import format

```bash
# Format: <zone-id>_<record-name>_<type>
tofu import $VARS aws_route53_record.fleet "Z02261701T34O15J8SXD2_fleet.internal.gift.id_A"
```

## OpenTofu: dynamic RDS SG rule for rebuild

When Fleet instance connects to RDS in another VPC, the RDS SG must allow the
instance's private IP. On rebuild, private IP changes. Use OpenTofu to manage
this rule dynamically:

```hcl
resource "aws_security_group_rule" "fleet_to_rds" {
  type              = "ingress"
  from_port         = 3306
  to_port           = 3306
  protocol          = "tcp"
  cidr_blocks       = ["${aws_instance.fleet_mdm.private_ip}/32"]
  security_group_id = var.rds_security_group_id
}
```

This way, `tofu apply` on a new instance automatically updates the RDS SG rule.
The `rds_security_group_id` variable points to the external RDS SG.

## OpenTofu: Route53 record as managed resource

Don't leave DNS records manual. Add to OpenTofu:

```hcl
data "aws_route53_zone" "internal" {
  name         = "internal.gift.id."
  private_zone = false
}

resource "aws_route53_record" "fleet" {
  zone_id = data.aws_route53_zone.internal.zone_id
  name    = "fleet.internal.gift.id"
  type    = "A"
  ttl     = 300
  records = [aws_eip.fleet_mdm.public_ip]
}
```

Points to EIP (not instance public IP) so DNS is stable across instance rebuilds.

## Wazuh: full ossec.conf template

The default Wazuh agent config is ~170 lines. When templating, match the live
config byte-for-byte including:
- Comment header (`More info at:` not `More info:` — exact wording matters)
- All `<rootcheck>`, `<wodle>`, `<syscheck>`, `<sca>`, `<localfile>` sections
- Two separate `<ossec_config>` blocks (main config + localfile monitors)
- Nginx log monitoring entries (`/var/log/nginx/access.log`, `error.log`)

Only the `<address>`, `<port>`, `<protocol>`, `<config-profile>`,
`<crypto_method>`, and `<agent_name>` values should be templated variables.

## Fleet: systemd unit ExecStop quirk

The live fleet.service uses a non-standard ExecStop:
```
ExecStop=/bin/kill -15 $(ps aux | grep "fleet serve" | grep -v grep | awk '{print$2}')
```

This is fragile (subshell in systemd) but matches the live unit. Template it
as-is. Fleet doesn't respond to standard `SIGTERM` from systemd reliably.

## Verification: comprehensive gap closure check

After gap closure, run a single ad-hoc verification script checking:

1. OpenTofu: fmt, validate, plan (0 diffs), state list (resource count)
2. Ansible: syntax-check, playbook ordering (certbot before nginx, etc.)
3. Templates: render each .j2 with real values, compare to live via SSM
4. Task content: grep for key task names (prepare db, fleetctl package, etc.)
5. Defaults: verify version numbers, URLs, server addresses
6. group_vars: verify vault references, use_rds flag
7. Secrets: `git grep` for known passwords from instance configs
8. Live: healthz endpoint returns 200
9. Artifacts: no macOS `._*` files

48 checks covering all aspects is typical for a Fleet MDM IaC repo.
